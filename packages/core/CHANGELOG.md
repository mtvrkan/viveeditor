# @viveeditor/core

## 1.0.0-rc.0

### Major Changes

- 095b69b: viveEditor 1.0: the public API is stable and follows semantic versioning. Breaking changes come only in a new major version, deprecated APIs stay for at least six months, and security fixes reach the previous major for six months. Upgrading from 0.x: `Draft` is now `AutosaveDraft`, `PasteOptionsOptions` is now `PasteOptionsSettings`, and `MountDestroyedError` is a `ViveEditorError` with the code `DESTROYED`; see the versioning page for the full guide.

### Minor Changes

- 9f59c19: Right-clicking a table, image, link, code block, video or formula opens a menu with the actions for that object, with submenus for cell, row and column actions. Plain text keeps the browser's own menu so spelling suggestions stay; Shift+right-click always shows the browser menu, Shift+F10 or the menu key opens it from the keyboard, and touch devices are left alone. The new `contextMenu` UI option (`'objects'`, `'always'` or `false`) controls it. Menus support submenus. Core gains the `selectAt` command and ext-embed the `selectedEmbedUrl` query.
- e8c82d0: Core hooks for comments, track changes and collaboration. An extension can set `replacesHistory: true` so the core history is left out and its own `undo` and `redo` commands are used (both answer false if it registers none). `transformTransaction(transaction, state, context)` lets an extension rewrite a local edit before it is applied, in priority order; it is skipped for remote and selection-only transactions, and a result built for another state is reported as `INVALID_TRANSACTION` and the original edit is kept. `isRemote(transaction)` and `REMOTE_META` mark edits from a peer or a sync, and the `change` event now carries `remote`. Autosave and the character limit ignore remote edits.
- 96ea657: Document tools and drafts. `@viveeditor/core` adds the queries `findNodes(names)` and `findMarks(names)`, which return `FoundItem { name, attrs, text, from, to }` in document order (at most 2000). `@viveeditor/ui` adds outline, accessibility check, keyboard shortcut list (Alt+0) and full screen to the toolbar, the `exclude` option to leave tools out, and autosave: `createAutosave(editor, options)` or `autosave` on `createUI` keeps a draft under `viveeditor:draft:<key>`, shows a bar to restore or delete it, and can call your own `save` function; `EditorUI` gains `autosave`. `messages` also accepts the new `DocumentMessages` keys. The panel kit exports `createOutlinePanel`, `createCheckPanel`, `createShortcutsPanel` and `documentMessages`. `viveeditor` reads `data-autosave="key"` on a textarea and clears the draft after a submit, and its panels add-on now carries the special characters panel and the new panels.
- 96ea657: New `FormatPainter` extension (part of `formatExtensions`) with `copyFormat`, `applyFormat`, `cancelFormat` and the `isPaintingFormat` query: copied marks are applied to the next mouse selection, or to a Shift-arrow selection when Shift is released, and Escape cancels; links in the target stay. The toolbar gets a "Format painter" button, `ToolSpec` gains `activeQuery`, and the core stylesheet shows a copy cursor while painting.
- 96ea657: Image captions and positions, table cell colour and vertical alignment. `@viveeditor/ext-image` gives the image node `caption` and `align` (`'left' | 'center' | 'right'`, exported as `ImageAlign`), set through `setImageAttributes` and returned by `selectedImage`; an image with either is written as `<figure data-align><img><figcaption>`, one with neither stays a plain `<img>`. `@viveeditor/ext-table` gives cells `background` and `verticalAlign` with `setCellBackground`, `setCellVerticalAlign` and `query.cellStyle()`. `@viveeditor/core` now exports `normalizeColor` (still re-exported by `@viveeditor/ext-format`, whose highlight no longer picks up a cell background). The interface adds caption and position to the image panel and cell colour and vertical alignment to the table panel. `@viveeditor/sanitize` keeps `figure` with a checked `data-align`, `figcaption` and the two cell styles; its profile gains `imageAlign` and `verticalAlign`. Both sanitizers now also drop fully transparent `hsl()` and `hsla()` colours. `@viveeditor/docx` writes and reads cell shading and vertical alignment and writes captions as Caption paragraphs; `@viveeditor/markdown` writes a caption as an italic line under the image.
  
  `getJSON()` now writes `caption: null, align: null` on every image and `background: null, verticalAlign: null` on every table cell. Documents from 0.1.0 load unchanged and their HTML and Markdown output is identical, but code that compares `getJSON()` output with a stored object must allow the new attributes.
- 96ea657: Paste as plain text with Ctrl/⌘+Shift+V: the clipboard formatting is dropped, the text takes the style around the cursor, and Markdown or video-embed conversion is skipped. Where the browser has no built-in shortcut, the editor reads the clipboard itself.
- 96ea657: `editor.getJSON()` writes `schemaVersion` (exported as `SCHEMA_VERSION`) at the root of the document. JSON without it loads as 0.x content; JSON with a newer version is refused with `ViveEditorError` code `SCHEMA_TOO_NEW`, and `replaceContent`/`insertContent` return `false` for it. Code that compares `getJSON()` output with a stored object must allow the new root key.
- 96ea657: Writing tools. `@viveeditor/ext-format` adds `Subscript`, `Superscript`, `FontSize` (`FONT_SIZES`, `setFontSize`, `unsetFontSize`, `stepFontSize`), `Indent` (`indent`, `outdent`, `indentLevel`), `ChangeCase` (`changeCase`, `cycleCase`, language-aware) and `Typography` (smart quotes, dashes, ellipsis and symbols), all part of `formatExtensions`; `ClearFormatting` now also resets `indent`. `@viveeditor/core` exports `textInputRule`. The interface adds a "Text style" menu, indent items in the alignment menu and a lazy special characters panel. `@viveeditor/sanitize` keeps `<sub>`, plain `<sup>`, editor font sizes on `span` and indent on paragraphs and headings, and drops nested font sizes and nested superscript or subscript; its profile gains `fontSizes` and `indents`. `@viveeditor/docx` maps superscript and subscript to `w:vertAlign`.
  
  `getJSON()` now writes `indent: null` on every paragraph and heading. Documents from 0.1.0 load unchanged, but code that compares `getJSON()` output with a stored object must allow the new attribute.

### Patch Changes

- 1a1a861: `getHTML()` writes font families exactly as the font list has them in every browser, so the saved HTML matches the sanitizer's output. A font whose first name is the first name of a list entry now maps to that entry, so fonts pasted from Word or Google Docs (`"Times New Roman",serif`, `Arial`) are kept; the Node and PHP sanitizers follow the same rule. Word's 100%, 115%, 150% and 200% line heights are read as 1, 1.15, 1.5 and 2. The font size and font family queries return `null` for a mixed selection.
- 96ea657: Fixes before 1.0. `@viveeditor/core` keeps leading, trailing and repeated spaces inside footnotes when the document is saved and loaded again. `@viveeditor/markdown` writes complete video links: the Vimeo private link part and the YouTube or Vimeo start time are kept. `@viveeditor/ui` applies the HTML typed in the source view before its form is submitted, also when a script calls `form.requestSubmit()`. `viveeditor`: `MountDestroyedError` is now a `ViveEditorError` with the code `DESTROYED`.
- 319b968: Keyboard shortcuts from all extensions are looked up in one table, so an exact match such as Ctrl+Shift+E (center) wins over another extension's shortcut without Shift (Ctrl+E, inline code). With Caps Lock on in Windows and Linux, Ctrl+Shift+E used to turn the selection into inline code. Bindings for the same key from several extensions still run in priority order until one handles the key.
